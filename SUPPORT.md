# Support

## Getting help

For general usage questions, bug reports, and feature requests:

- open an issue with clear reproduction steps
- include your deployment method and relevant version or commit information
- sanitize logs, artifacts, hostnames, paths, and credentials before sharing

## Before opening an issue

- read [README.md](./README.md)
- check [docs/README.md](./docs/README.md)
- review [CONTRIBUTING.md](./CONTRIBUTING.md) if you are preparing a fix

## Security issues

Do not file public issues for vulnerabilities. Use [SECURITY.md](./SECURITY.md).

## Scope of support

This project currently follows a source-first support model:

- `main` is supported on a best-effort basis.
- If tagged releases are published, support is expected to focus on `main` plus the latest tagged release unless a newer policy says otherwise.
- Docker images, when published, are convenience artifacts and do not imply a separate long-term support stream.

Older local forks, heavily modified deployments, and stale unpublished commits may require self-service debugging.
